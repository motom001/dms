## Neu

- **Paket selbst erstellen** (#374): Unter Werkbank → Pakete → **Paket erstellen** machst du aus eigenen Mappentypen und Ansichten ein Paket im Format der Registry und nimmst es als `.zip` in ein anderes DMS mit (dort: Expertenmodus → Paket hochladen).
  - Assistent in vier Schritten: **Auswählen** (mit Suche, optional ausdrücklich gewählte Beispiel-Mappen), **Prüfen** (automatisch), **Angaben** (Name, Id, Version, Beschreibung, Autor, Lizenz aus der Liste der Registry, nötige DMS-Version, Änderungen), **Exportieren**.
  - Typen und Ansichten aus installierten Paketen kommen als **Abhängigkeit** (`>=` installierte Version) statt als Kopie; Verweise auf Benutzer, Rolle und Ablageort werden `dms:…`; eigene, nicht gewählte Typen meldet die Prüfung mit „Mit aufnehmen“; lokal geänderte Paket-Typen bekommen einen Hinweis.
  - Vor dem Download dieselbe Prüfung wie beim Hochladen. Das Paket enthält README, CHANGELOG, den vollen Lizenztext und `tests/erwartung.yaml` und besteht `pruefen.py` der Registry.
  - Keine Mappendaten, Benutzer oder Passwörter im Paket. Id, Version, Autor, Lizenz und Auswahl werden gemerkt: Der nächste Export schlägt dieselbe Id mit höherer Version vor, das andere DMS aktualisiert dann.
- Handbücher: *Pakete → Paket aus deinem DMS erstellen* (Administratoren), *Pakete entwickeln → Paket aus deinem DMS erstellen*.

## Noch nicht dabei

- Nummernkreise, weitere Trefferlisten, Berechtigungen, Archivmodus und Bedingungen auf Anzahlen, Favoriten oder Fristen kennt das Paketformat nicht; sie bleiben draußen (die Prüfung nennt sie).
- „In dms-registry einreichen“ (Pull Request vorbereiten) kommt mit einem eigenen Issue.
