# Contributing

[Deutsch](CONTRIBUTING.md) · **English**

Thank you for your interest in Ablago! **Issues and pull requests are welcome in German or English.** How contributing works here is described in detail in the **[developer manual](https://help.ablago.app/entwickler/aktuell/en/)**. The essentials in brief:

1. **Start with an issue**, written as a user story ("As a … I want …, so that …") with acceptance criteria. This applies to feature requests and bugs alike.
2. **Discussion happens in the issue** until it is clear what will be built.
3. **Only issues labelled `freigegeben` (approved) get implemented.** This label is set by the maintainer ([@motom001](https://github.com/motom001)) alone. Pull requests for issues that are not approved will not be merged.
4. **Pull request** with `Closes #…`, tests, an updated manual and – if it changes the program – a notes snippet `docs/releases/neu/<branch>.md` (first line `art: patch`, `art: minor` or `art: keine`, below it the release notes). The version number is assigned on merge (developer manual → Release). Only the maintainer merges.

## New dependencies only with a reason

Ablago gets by with very little third-party code – this protects against supply-chain attacks and keeps maintenance and the image small. A **new runtime dependency** (an npm package under `dependencies`, or an Alpine package via `apk add` in the `Dockerfile`) is therefore only accepted with a reason given in the pull request:

- **What for** is it needed?
- **Why not** with what Node.js already provides, or with the dependencies and tools already in use?
- **Licence** – compatible with Apache-2.0?
- **Maintenance** – latest release, number of maintainers?
- **Its own dependencies** – what else does it bring into the image?

The pull request template asks for this; the "Abhängigkeiten" (dependencies) check points out new dependencies in the PR. The current list with the purpose of each is in the [developer manual](https://help.ablago.app/entwickler/aktuell/en/aufbau/#abhaengigkeiten).

## Checking style and dependencies

Before the pull request, `npm run lint` (ESLint with type information) and `npm run lint:abh` (dependency-cruiser) pass without errors. Whatever existed when they were introduced is listed in `eslint-suppressions.json` or `.dependency-cruiser-known-violations.json` and is not reported – new code is fully strict, and the lists must not grow: **move yes, add no**. Exceptions in the code only with a reason (`// eslint-disable-next-line rule -- reason`). Details in the [developer manual](https://help.ablago.app/entwickler/aktuell/en/stil/).

## Graphics and images per language

Graphics containing text exist per language: `name.svg` in German, `name.en.svg` in English (e.g. `personas-skala.svg` and `personas-skala.en.svg`, generated by `docs/handbuch/werkzeuge/personas_grafiken.py`). `README.md` embeds the German ones, `README.en.md` only the `.en` versions. The only exception are screenshots of the user interface: as long as they exist in German only (#357), `README.en.md` shows the German image with a note that the interface is currently available in German only. A test (`server/test/readme-sprachen.test.ts`) checks this.

By contributing, you license your contribution under the [Apache-2.0](LICENSE). Please do not commit real documents or personal data.

Ablago's user interface (#729) and its manuals (#730) are available in German and English. You do not need to speak German to report a bug, suggest a feature or send a pull request.
